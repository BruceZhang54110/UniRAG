## User Scenarios & Testing *(mandatory)*

> **本期范围说明**：建立一套**离线、可复现的检索评测能力**：用冻结的语料、查询集与人工相关性标注，对现有检索链路（查询改写、逐表向量检索、归并、重排）计算检索质量指标，产出可比较的基线报告。本期只评检索，不评回答生成质量；不引入 LLM-as-judge、A/B 实验平台或自动调参。评测运行与默认质量门分离：默认测试保持确定性且不依赖外部模型凭据，评测运行按需显式触发。

### User Story 1 - 一键复现检索基线 (Priority: P1)

评测维护者拿到一份已冻结的评测数据集（语料、查询、标注、运行配置），执行一次评测命令，系统完成语料摄取、逐条检索、指标计算与报告输出。报告包含总体指标、分维度指标和每条查询的命中详情，维护者无需手工整理数据即可判断当前检索能力处于什么水平。

**Why this priority**: 当前仓库没有检索效果评测。011 的重排与 012 的查询改写都定义了可量化的成功标准，但没有基线就无法验证，也无法判断后续是否值得引入混合检索、切片优化等能力。这是所有检索优化的前置条件。

**Independent Test**: 使用固定的小型数据集与确定性复现模式运行评测，断言报告生成、指标数值可重复、每条查询都有命中详情；连续运行两次得到完全相同的指标。

**Acceptance Scenarios**:

1. **Given** 一份通过校验的评测数据集与配置，**When** 执行评测，**Then** 系统完成语料摄取与全部查询检索，产出一份报告，包含总体指标、分标签指标与每条查询的 top-k 命中详情。
2. **Given** 同一份数据集、同一配置、同一复现模式，**When** 连续执行两次评测，**Then** 两次报告的指标数值完全一致。
3. **Given** 数据集存在重复查询标识、标注指向不存在的文档、标注片段在文档中找不到或配置缺失，**When** 执行评测，**Then** 系统在摄取前拒绝运行，给出可定位的错误，不产出"部分成功"的基线。
4. **Given** 维护者只运行默认质量门，**When** 未显式触发评测，**Then** 评测不执行、不产生外部模型调用、不要求任何模型凭据。
5. **Given** 评测数据集与配置已准备好，**When** 新增或替换语料与查询但未修改任何代码，**Then** 评测仍可运行并产出报告。

---

### User Story 2 - 比较版本并阻止检索退化 (Priority: P2)

维护者在修改切片、改写、重排、召回条数或相似度阈值后，用同一数据集重新评测，并把新报告与基线报告比较。系统给出每个指标与每个标签维度的变化，明确标出退化项；当两次运行的数据集或关键配置不可比时，系统拒绝直接比较并说明原因。

**Why this priority**: 基线的价值在于比较。没有比较与门槛，任何检索改动都只能靠主观判断，容易出现"修好一个问题、弄坏另一个场景"。

**Independent Test**: 用两份配置不同但数据相同的报告做比较，断言指标差值与手工计算一致；用数据集或模型配置不同的报告做比较，断言系统拒绝并给出不可比原因；用阈值配置构造退化场景，断言退化项被标记。

**Acceptance Scenarios**:

1. **Given** 基线报告与候选报告使用相同数据集、相同模型与相同关键配置，**When** 执行比较，**Then** 输出每个指标及每个标签维度的绝对差值与相对变化，并标记退化项。
2. **Given** 两次运行的语料、查询集、模型标识或切片配置不同，**When** 执行比较，**Then** 系统拒绝给出结论，并列出不可比的具体字段。
3. **Given** 维护者配置了指标阈值，**When** 候选报告低于阈值，**Then** 比较结果明确标记该项未通过。
4. **Given** 尚未配置阈值，**When** 首次生成基线，**Then** 系统只记录数值，不判定通过或失败。

---

### User Story 3 - 定位失败发生在哪一层 (Priority: P3)

维护者查看报告中的失败查询时，能直接看到问题属于哪一类：答案片段没有被切出来、切出来了但没有被召回、召回后被相似度阈值过滤、多表归并或去重导致丢失，还是标注本身不成立。每条失败查询都附带 top-k 的文档、片段序号、分数与相关性判断。

**Why this priority**: 只有知道失败发生在切片、召回、阈值还是归并层，才能决定下一步投入方向。否则容易把切片问题误判为需要混合检索。

**Independent Test**: 构造四类确定性失败样本（切片缺失、排序靠后、阈值过滤、标注错误），断言报告分别给出对应归因；构造成功样本，断言不产生误报。

**Acceptance Scenarios**:

1. **Given** 某条可回答查询未命中任何相关片段，**When** 查看报告，**Then** 系统给出失败归因，并说明依据（例如相关片段未出现在语料切分结果中）。
2. **Given** 相关片段已被切出但未进入 top-k，**When** 查看报告，**Then** 系统标记为召回/排序问题，并给出该片段实际所在位置或"未进入候选集"。
3. **Given** 相关片段进入候选集但被相似度阈值过滤，**When** 查看报告，**Then** 系统标记为阈值问题，并给出过滤前的分数。
4. **Given** 多管线产生重复或近似重复片段，**When** 查看报告，**Then** 文档级与片段级指标分别给出，且报告说明去重口径。

---

### User Story 4 - 领域专家维护评测数据集 (Priority: P4)

领域专家或评测维护者可以按约定格式新增语料、查询与相关性标注，系统在运行前完成结构校验，并拒绝会破坏可比性的改动（重复标识、缺失标注、标注片段不存在等）。数据集的每次变更都被版本化，作为新基线的一部分。

**Why this priority**: 评测集是长期资产，必须能持续扩充和修正，而不是写死在代码里。它是 P1–P3 可持续的前提，但不阻塞首版基线交付。

**Independent Test**: 仅通过数据文件新增一篇文档与一条查询，断言评测可运行；构造重复标识、缺失标注、片段不存在的数据集，断言校验失败并定位到具体条目。

**Acceptance Scenarios**:

1. **Given** 维护者新增语料与查询文件，**When** 执行评测，**Then** 系统自动纳入新数据，无需修改代码或重建评测程序。
2. **Given** 标注引用的文档不存在或片段在文档中找不到，**When** 执行评测，**Then** 校验失败并指出查询标识、文档标识与缺失内容。
3. **Given** 数据集内容发生变化，**When** 生成报告，**Then** 报告记录新的数据集版本标识，旧基线与新运行被判定为不可直接比较。

---

### Edge Cases

- 语料为空、查询集为空或全部查询不可回答——校验失败或明确报告"无有效样本"，不得产出看似正常的空基线。
- 查询标识重复、标注重复或同一查询同时标记为可回答与不可回答——校验失败并定位到具体查询。
- 可回答查询没有任何相关性标注，或不可回答查询带有标注——校验失败。
- 标注片段在一篇文档中出现多次——按文档级与片段级分别匹配，报告中说明匹配口径。
- 相关片段在切分阶段被截断或跨片段拆分——归因为切片问题，不得误判为召回问题。
- 语料摄取部分失败——评测失败并列出失败文档；不得用残缺索引生成基线。
- 显式复现模式缺少所需的冻结数据——失败并说明缺失项，不得回退到外部模型。
- 按需真实模型模式不可用、超时或限流——评测失败并给出原因；不得产出"部分成功"的报告。
- 模型标识或版本发生变化——新旧报告判定为不可直接比较。
- 切片参数、召回条数、相似度阈值、改写或重排开关变化——报告记录变更；比较时区分"配置变化"与"效果变化"。
- 相同内容重复摄取——不得静默复用旧切片或旧向量；配置变化时必须重建评测索引。
- 多条管线召回同一文档的不同片段——文档级指标按文档去重，片段级指标保留重复，两者都报告。
- 相似度阈值过滤掉全部候选——报告必须区分"没有召回"与"召回后被阈值过滤"。
- 报告目录已存在同名结果或并发运行两次评测——不得覆盖彼此结果；应生成可区分的新报告或明确拒绝。
- 比较的两份报告数据集、模型或关键配置不同——拒绝比较并列出不可比字段。
- 评测租户缺失、被禁用或配置失效——失败并给出可定位原因，不影响其他租户。
- 语料包含敏感信息——评测数据必须为可入库的测试语料；报告与日志不得包含模型凭据。
- 查询或文档极长、混合语言、纯符号——按既有输入校验语义处理，不得让单条样本拖垮整轮评测。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 评测 MUST 由四类可版本控制的产物组成：语料文档、查询用例、相关性标注、运行配置。四者 MUST 自包含，不得依赖代码中的隐式常量。
- **FR-002**: 每条查询 MUST 包含唯一标识、原始问题、标签维度、是否可回答，以及可回答时的相关性标注；标注 MUST 指向文档标识与原文片段，不得指向易变的片段序号。
- **FR-003**: 系统 MUST 在摄取前校验数据集：标识唯一、标注文档存在、标注片段可在文档中找到、可回答与不可回答语义一致、配置完整。任一校验失败 MUST 终止运行并给出可定位的错误。
- **FR-004**: 评测 MUST 在专用评测租户内执行，MUST NOT 读写非评测租户的数据；运行前后 MUST 可清理评测数据，重复运行不得累积脏数据。
- **FR-005**: 系统 MUST 支持一次触发完成"摄取语料 → 执行全部查询 → 计算指标 → 输出报告"，不得要求人工分步操作或手工汇总。
- **FR-006**: 报告 MUST 至少包含以下指标：Recall@k、HitRate@k、MRR@k、nDCG@k、不可回答问题误答率、检索耗时 p50 与 p95；k 的取值 MUST 可配置。
- **FR-007**: 报告 MUST 同时提供总体指标、按标签维度的指标，以及每条查询的 top-k 命中详情（文档标识、片段序号、分数、是否相关、首个相关结果排名）。
- **FR-008**: 报告 MUST 记录运行快照：数据集版本、语料与查询集标识、代码版本、模型标识、切片参数、召回条数、相似度阈值、改写与重排开关、运行模式、运行时间。
- **FR-009**: 系统 MUST 支持显式复现模式：同一数据集、同一配置、同一冻结输入下重复运行，指标 MUST 完全一致，且 MUST NOT 依赖外部模型凭据。
- **FR-010**: 系统 MUST 支持按需真实模型模式；该模式 MUST 显式触发，失败时 MUST 明确报错，MUST NOT 产出部分成功的基线。
- **FR-011**: 切片参数、向量化配置或模型标识变化时，评测 MUST 重建评测索引；相同内容重复摄取 MUST NOT 静默复用旧切片或旧向量。
- **FR-012**: 系统 MUST 支持比较两份报告：数据集与关键配置一致时给出各指标及分标签维度的差值与退化标记；不一致时 MUST 拒绝比较并列出不可比字段。
- **FR-013**: 指标阈值 MUST 可配置。首次基线 MUST 只记录数值不判定通过或失败；配置阈值后，比较结果 MUST 明确标记未通过项。
- **FR-014**: 对未命中的可回答查询，报告 MUST 给出失败归因，至少区分：答案片段未被切分覆盖、片段已存在但未进入候选集、进入候选集但被阈值过滤、多表归并或去重导致丢失、标注本身不成立。归因 MUST 基于可观察数据，不得猜测。
- **FR-015**: 多管线场景下，报告 MUST 同时给出文档级与片段级指标，并明确去重口径；两者不得混为一个数字。
- **FR-016**: 数据集扩展 MUST 只通过数据文件完成，不得要求修改评测代码；新增语料与查询后 MUST 能直接参与运行。
- **FR-017**: 评测 MUST 与默认质量门分离：默认质量门保持确定性、无需外部模型凭据；评测按需触发，MUST NOT 改变默认质量门的通过/失败结果，MUST NOT 为默认质量门新增外部模型调用或凭据要求。
- **FR-018**: 报告、日志与错误信息 MUST NOT 包含任何模型凭据、密码或令牌；评测语料 MUST 为可入库的测试数据，不得包含生产敏感内容。
- **FR-019**: 每次运行 MUST 可追溯到唯一的数据集版本与配置快照；数据集或关键配置变化 MUST 视为新基线，不得与旧基线直接混用。
- **FR-020**: 本期 MUST NOT 引入回答生成质量评测、LLM-as-judge、A/B 实验平台、自动调参或评测管理界面。

**明确不在本期范围**：

- 回答质量评测（groundedness、引用支持度、拒答正确性）与 LLM-as-judge
- A/B 实验、线上流量分流、观察模式的数据采集（011/012 已有观察模式，本期只消费其结果）
- 自动调参、自动阈值学习、自动提示词优化
- 评测管理界面、可视化大屏
- 生产环境监控与告警
- 合成数据生成、跨租户共享评测集
- 嵌入模型迁移与向量索引调优

### Key Entities *(include if feature involves data)*

- **评测数据集（Evaluation Dataset）**: 一轮评测的完整输入，包含语料、查询、标注与配置四部分，具有可识别的版本。
- **语料文档（Corpus Document）**: 评测用文档，具有稳定标识与正文；与查询标注通过文档标识关联。
- **查询用例（Query Case）**: 一条待评测问题，属性包括唯一标识、问题文本、标签维度、是否可回答、所属数据划分（开发/测试）。
- **相关性标注（Relevance Label）**: 查询与语料之间的相关性证据，属性包括文档标识与原文片段；一个查询可有多条标注。
- **评测配置（Evaluation Configuration）**: 本轮运行使用的切片、向量化、召回、阈值、改写、重排与指标参数。
- **评测运行（Evaluation Run）**: 一次完整执行，包含数据集版本、配置快照、运行模式、时间与结果状态。
- **评测报告（Evaluation Report）**: 一次运行的输出，包含总体指标、分维度指标、逐查询详情、失败归因与配置快照。
- **指标结果（Metric Result）**: 某个指标在总体或某个标签维度上的取值，可带阈值与通过状态。
- **基线比较（Baseline Comparison）**: 两份报告之间的差值与退化判定，以及不可比原因的说明。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在 10 篇文档、30 条查询的规模下，维护者可从干净检出开始，用一次触发完成摄取、检索、指标计算与报告输出，全过程不超过 10 分钟（不含模型下载与首次环境准备）。
- **SC-002**: 在显式复现模式下，同一数据集与配置连续运行 3 次，3 次报告的全部指标数值完全一致，一致率 100%。
- **SC-003**: 报告覆盖 100% 的查询与 100% 的配置指标，不得出现缺失值；每条查询都必须有 top-k 命中详情。
- **SC-004**: 100% 的非法数据集（重复标识、缺失标注、标注片段不存在、配置缺失）在摄取前被拒绝，并给出可定位到具体条目的错误。
- **SC-005**: 一次评测运行对非评测租户的数据变更量为 0，运行前后非评测租户的数据指纹一致。
- **SC-006**: 报告比较功能对不可比配置的拒绝率为 100%；可比配置下的指标差值与手工计算结果一致，退化标记无漏报。
- **SC-007**: 100% 的未命中查询都有失败归因与 top-k 详情；归因结论与构造的确定性失败样本一致。
- **SC-008**: 检查 100% 的报告、日志与错误输出，均不包含模型凭据、密码或令牌。
- **SC-009**: 新增 10 篇文档与 30 条查询时，100% 的数据集扩展只通过数据文件完成，无需修改评测代码。
- **SC-010**: 默认质量门在引入评测能力前后，测试通过率保持 100%，总耗时变化不超过 20%；评测能力为默认质量门引入的外部模型凭据依赖为 0。

## Assumptions

- 本期只评检索质量；回答生成质量作为后续 feature，复用本期数据集与报告结构。
- 首版评测集规模为 10–50 篇文档、30–100 条查询；其中不可回答查询占 10%–20%。
- 相关性标注按文档标识与原文片段表达，而不是按片段序号，以兼容切片参数变化。
- 显式复现模式使用预先冻结的向量化结果；按需真实模型模式使用租户自己的模型资源。两种模式的报告分别标识，不可直接混比。
- 评测在开发或持续集成环境中的真实数据库上运行，不连接生产库；评测租户独立于业务租户。
- 评测语料是可入库的测试内容，不包含生产敏感数据；报告可保留片段原文用于排障。
- 默认质量门继续使用确定性替身，评测运行不属于默认质量门。
- 首版报告以文件形式输出，不提供管理界面；维护者通过阅读报告与比较结果完成分析。
- 阈值在首版基线完成后由维护者配置；首版运行只建立数值基线，不做通过/失败判定。
- 评测的触发方式可以是人工命令或定时任务，但必须显式、可追溯、可重复。
