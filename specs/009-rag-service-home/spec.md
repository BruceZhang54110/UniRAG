# Feature Specification: RAG 服务首页（混合式提问台与知识导航）

**Feature Branch**: `[009-rag-service-home]`

**Created**: 2026-10-11

**Status**: Draft

**Input**: User description: "进行 C. 混合式页面工作 —— RAG 服务首页：以提问台为主体，辅以一层知识导航，普通用户访问时不展示租户入口"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 无前置步骤直接提问 (Priority: P1)

普通用户打开服务首页，立即看到提问输入框，输入自己的问题并提交，随后进入问答以获得答案。整个过程中用户不需要登录、不需要理解或选择任何"租户"，也不需要先浏览任何菜单。

**Why this priority**: 首页存在的唯一理由是让用户以最短路径开始提问。任何前置步骤（登录、租户选择、导航摸索）都会直接损失转化，因此这一条是所有其他能力的前提。

**Independent Test**: 在未做任何配置的环境中打开首页，确认可以直接输入并提交问题、并被带入问答上下文；同时确认页面上不出现任何租户相关元素。

**Acceptance Scenarios**:

1. **Given** 用户首次打开首页且知识库中已有可检索的文档，**When** 用户在提问框输入问题并提交，**Then** 系统携带该问题进入问答上下文并开始作答，用户无需任何登录或配置步骤。
2. **Given** 用户尚未输入任何内容，**When** 用户尝试提交，**Then** 系统不提交空问题、不跳转到错误页面，并保持输入焦点以便继续输入。
3. **Given** 用户正在输入多行问题，**When** 用户执行"换行"操作，**Then** 输入框内换行而不提交；仅当执行"提交"操作时才发送问题。
4. **Given** 首页处于任意状态，**When** 用户查看页面，**Then** 页面中不出现租户名称、租户编码或租户切换入口。

---

### User Story 2 - 浏览知识库里有什么 (Priority: P2)

没有明确问题的用户可以在首页看到知识库中最近更新的文档条目，并可进入完整文档列表继续浏览。用户由此判断"这里有没有我想要的内容"。

**Why this priority**: 相当一部分访客属于探索型而非提问型；纯提问入口对他们是空白页。内容线索同时证明知识库非空，是建立信任的最低成本手段。

**Independent Test**: 在有文档的知识库中打开首页，确认看到最近更新条目（名称与更新时间）、可查看单条文档详情、可进入完整列表。

**Acceptance Scenarios**:

1. **Given** 知识库中已有文档，**When** 用户查看首页的知识导航区域，**Then** 展示最近更新的文档条目（名称、更新时间），最多 6 条。
2. **Given** 用户点击某条最近更新文档，**When** 触发后，**Then** 展示该文档的详情，且浏览结束后用户仍停留在首页上下文。
3. **Given** 用户希望看到全部内容，**When** 用户选择"浏览全部文档"，**Then** 进入完整文档列表。
4. **Given** 某个文档名称超出显示宽度，**When** 条目被渲染，**Then** 名称单行截断，且用户可获得完整名称。

---

### User Story 3 - 空知识库时的启动引导 (Priority: P2)

新用户面对一个还没有任何文档的知识库时，首页明确告知"需要先有内容才能提问"，并提供一个直接的上传入口，让用户在同一个页面完成从零到可提问的转变。

**Why this priority**: 空状态是新产品最常被看到的状态。若空状态只显示一个不可用的输入框，用户会认为服务不可用而离开。上传能力已存在，缺的只是引导。

**Independent Test**: 在没有任何文档的环境中打开首页，确认提问被合理阻止、引导清晰、上传入口可达；上传一份文档后返回首页，确认提问恢复可用。

**Acceptance Scenarios**:

1. **Given** 知识库中没有任何文档，**When** 用户打开首页，**Then** 提问不可提交，并提示用户需要先上传文档。
2. **Given** 知识库中没有任何文档，**When** 用户查看知识导航区域，**Then** 展示三步启动引导（上传文档 → 等待自动处理 → 开始提问）并提供上传入口。
3. **Given** 用户从空状态上传文档并等待其可检索，**When** 用户回到首页，**Then** 提问恢复可用，且最近更新中出现该文档。
4. **Given** 知识库中没有任何文档，**When** 用户点击某条建议问题，**Then** 系统提示需要先上传文档，且不提交该问题。

---

### User Story 4 - 建议问题与回访继续 (Priority: P3)

不知道该问什么的用户可以通过首页给出的建议问题一键开始；此前用过服务的用户可以从首页直接回到最近一次对话继续。

**Why this priority**: 建议问题降低冷启动门槛，回访入口提升重复使用率。两者都不影响核心提问路径，因此优先级低于前三项。

**Independent Test**: 在知识库有内容的情况下，确认建议问题可一键提交；在有历史对话的情况下，确认可从首页一键恢复对话。

**Acceptance Scenarios**:

1. **Given** 知识库中有可检索文档，**When** 用户查看提问输入框附近，**Then** 展示 3 至 4 条建议问题，点击任一条即提交该问题。
2. **Given** 用户此前产生过对话，**When** 用户再次打开首页，**Then** 展示最近对话条目（问题摘要与时间），点击可恢复该对话继续。
3. **Given** 用户从未产生过对话，**When** 用户打开首页，**Then** 最近对话区域不渲染空容器，也不占用页面空间。

---

### Edge Cases

- **文档全部处于处理中**：知识库有文档但暂无可检索内容时，允许提问但明确提示"知识库正在处理中，部分问题可能没有结果"。
- **服务不可用**：后端无法访问时，首页给出可感知的告警与重试入口，并阻止会失败的提问提交，避免用户反复尝试。
- **首页数据加载中**：概览数据未返回时采用局部占位，提问输入框不因此被延迟渲染。
- **空知识库与加载失败的区别**：两者都必须被区分，不能把"请求失败"呈现为"知识库为空"，否则会误导用户上传已存在的文档。
- **长时间停留后提交**：用户停留很久后提交问题，若服务端会话上下文已失效，需给出明确提示并允许重试，而不是静默失败。
- **超长问题**：用户输入极长文本（数千字）时，页面布局不被破坏，提交行为可预期。
- **多标签页**：同一浏览器打开多个首页标签时，最近对话等本地状态允许最终一致，不要求实时同步。
- **窄屏设备**：在手机宽度下不出现横向滚动，提问入口与提交动作仍可完成。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 用户 MUST 无需登录、无需任何配置或选择动作即可打开首页并开始提问。
- **FR-002**: 首页 MUST NOT 展示任何租户相关信息（租户名称、编码、切换入口或提示文案）。
- **FR-003**: 首页 MUST 以提问输入为唯一第一视觉焦点，并提供明确的提交动作。
- **FR-004**: 系统 MUST 阻止空内容提交，且不产生错误页面。
- **FR-005**: 用户 MUST 能在输入框中换行而不触发提交，并能显式提交问题。
- **FR-006**: 用户提交问题后，系统 MUST 携带该问题进入问答上下文继续作答。
- **FR-007**: 首页 MUST 提供 3 至 4 条建议问题，点击即提交；当知识库无可提问内容时，建议问题 MUST 表现为不可用并给出原因。
- **FR-008**: 首页 MUST 展示最近更新的文档条目（最多 6 条，含名称与更新时间），并允许查看单条文档详情。
- **FR-009**: 首页 MUST 提供进入完整文档列表的入口。
- **FR-010**: 当知识库为空时，系统 MUST 禁用提问、说明原因，并展示"上传 → 处理 → 提问"的启动引导与上传入口。
- **FR-011**: 当知识库存在处理中内容且暂无可检索内容时，系统 MUST 提示处理中状态。
- **FR-012**: 当服务不可用时，系统 MUST 给出明确、可感知的提示与重试入口，并阻止必然失败的提问提交。
- **FR-013**: 系统 MUST 记录并在首页展示最近对话（最多 6 条，含问题摘要与时间），点击可恢复该对话。
- **FR-014**: 当用户没有历史对话时，系统 MUST NOT 渲染空的最近对话容器。
- **FR-015**: 首页的交互元素 MUST 支持键盘操作，包括聚焦提问输入框的快捷键。
- **FR-016**: 首页 MUST 适配桌面、平板与手机宽度：窄屏下不出现横向滚动，提问入口始终可达。
- **FR-017**: 首页所有面向用户的文案 MUST 使用中文。
- **FR-018**: 首页展示的文档、对话与统计信息 MUST 仅来源于当前用户身份可见的范围，不得泄漏其他范围的数据。

### Key Entities *(include if feature involves data)*

- **知识库概览**：描述当前知识库的可提问状态，包含文档总数、可检索数量、处理中数量；用于决定提问是否可用以及提示文案。
- **文档摘要**：用于知识导航展示，包含名称、标题、更新时间、文档类型；来源于已有的文档查询能力。
- **建议问题**：用于降低提问门槛，包含问题文本与来源（由文档标题生成或预设文本）。
- **会话摘要**：用于回访继续，包含问题摘要、最后活动时间与可恢复标识。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 首次访问者从打开首页到提交第一个问题，不超过 3 次交互、不超过 15 秒。
- **SC-002**: 在常规网络条件下，用户打开首页后 2 秒内看到可用的提问输入框。
- **SC-003**: 在首页的所有状态下，可见的租户相关元素数量为 0。
- **SC-004**: 面对空知识库的用户中，100% 能在首页找到上传入口（5 名用户可用性测试全部通过）。
- **SC-005**: 回访用户可在 1 次点击内恢复此前的对话。
- **SC-006**: 在桌面、笔记本与手机三种宽度下，首页均无横向滚动，且提问入口始终可见可达。
- **SC-007**: 服务不可用时，100% 的测试用户能识别出"当前不可用"并找到重试入口。
- **SC-008**: 5 名首次使用者中至少 4 名能在不被提示的情况下完成"打开首页 → 提出一个问题"的完整流程。

## Assumptions

- **知识库共享**：普通用户共用同一知识库；租户由系统内部解析，用户无感知，页面不承担任何身份选择职责。若将来改为"每个用户独立知识库"，需先引入登录，本页的布局与交互不受影响。
- **上传人人可用**：当前不存在角色与权限模型，因此所有访问者都视为可以上传文档；空状态引导据此设计。
- **问答由独立页面承载**：首页只负责发起提问，不承载对话历史与答案渲染。
- **已有能力复用**：文档的列表、详情、下载以及知识库统计信息均由既有后端能力提供，本功能不新增数据来源。
- **最近对话保存在浏览器本地**：不依赖服务端会话存储，因此换设备或清理浏览器数据后不保证可恢复。
- **语言与终端**：界面为中文，桌面优先，移动端为可用级支持而非体验优化目标。
- **明确不做**：不提供登录页、不做租户选择、不做热门问题或分类聚合（当前无相应数据来源）、不在首页内联展示答案、不做管理类仪表盘。
